# SINA — Working Rules for Claude

SINA is a governed design system for AI agents: an LLM emits *intent*, SINA validates it against Zod schemas (the "Constitution") **server-side**, and either blocks the stream or mounts an accessible, governed React primitive. The principle is **validate-then-mount** — never mount, then check. It's free and made for startups and individuals who want a design system with governance built in, so they can adopt agentic UI generation without building the governance layer themselves.

This file is **binding**. `ROADMAP.md` explains the *why* and the phase sequencing; this file is the *rules*.

## Architectural boundaries (hard rules)

These mirror the per-package ESLint `no-restricted-imports` messages, so the agent and the linter say the same thing. A hand-off that would violate one of these must be pushed back on, with a proposal for where the concern belongs.

- **`@sina-design-system/theme`** — design tokens (the `--sina-*` CSS custom properties in `theme.css`) + the CSS reset (`reset.css`) only. **No React, no react-dom, no Tailwind.** (Ships `./css` + `./reset.css`; there is no Tailwind preset.)
- **`@sina-design-system/core`** — headless, accessible primitives on Radix, styled with **co-located CSS Modules** (`<Name>.module.css`) that consume `theme` tokens (see the Styling convention). **No `zod`, no domain packages (`fintech`/`defense`), no domain *vocabulary*** (no `$50,000`, NSN, CAC, "limit", "approval"), and **no Tailwind / `class-variance-authority`**. Strictly domain-agnostic.
- **`@sina-design-system/fintech`** (and future `defense`) — pure Zod constitution. **No React, no `core`, no `theme`, no UI of any kind.**
- **`@sina-design-system/fintech-react`** — governed components (the third layer): composes a `core` primitive with a `fintech` schema and renders the decision the gate already made. **The one package allowed to import both `core` and `fintech`** (+ `theme`/`governance`). Still **no `zod`** (it composes schemas, never authors them) and **no `defense`**. The gate stays server-side — these components never validate a payload.

**The one invariant (ROADMAP §1b):** the model emits **intent + props, never a component**. Validation runs **server-side only**; client-side checks are untrusted UX sugar. We **validate, then mount** — RSC tokens already streamed cannot be un-rendered, so the schema gate sits *before* any `core` primitive mounts.

## Conventions

- **Naming:** libraries are scoped `@sina-design-system/*`; apps are bare (`web`, `playground`).
- **Layout:** `src/index.ts` is the public surface (named exports only — no default exports for library code); tests co-located as `src/**/*.test.ts(x)`; ESM (`"type": "module"`). UI packages (`core`, `fintech-react`) build via **Vite library mode** (`vite build` → `dist/*.js` with `preserveModules` + one extracted `dist/styles.css`) plus **`tsc --emitDeclarationOnly`** (`tsconfig.build.json`) for `.d.ts`; they set `"sideEffects": ["**/*.css"]` and export `"./styles.css"`. Pure-logic packages (`theme`, `fintech`, `governance`) still build via `tsc`. The `exports` map points at `dist`.
- **Stub/banner style:** every `src/index.ts` opens with a block comment naming the package and its boundary; match the existing stubs when adding files.
- **Styling = co-located CSS Modules (no Tailwind).** Each component pairs `<Name>.tsx` with `<Name>.module.css`: `import styles from "./<Name>.module.css"` and compose with `cn()` (now just `clsx`) → `cn(styles.root, styles[variant], className)`. Flat class names, real pseudo-classes for state, no CSS nesting. Each module declares a per-component `--sina-<name>-*` token layer aliasing the semantic `--sina-*` tokens (mirrors the remarkable-sandbox pattern); the cheat-sheet is `packages/core/CSS_TOKENS.md`. **Cascade contract:** `packages/theme/reset.css` lives in `@layer reset`; component + app CSS are unlayered and win over it, and an app's CSS beats a component's by source order (layout.tsx imports theme reset → tokens → component `styles.css`, then app CSS last). Radix enter/exit animations are hand-authored `@keyframes` driven by `--sina-duration--*` (reduced-motion is zeroed at the token layer).
- **Colors are authored in hex only** (`#rrggbb`, or `#rrggbbaa` for baked-in alpha) in `packages/theme/theme.css` — never RGB channels, `rgb()/hsl()/oklch()`, or named colors. A vitest guard in `packages/theme/src/tokens.test.ts` fails the build on any non-hex color token. **Component `*.module.css` never write a raw color** — only `var(--sina-*)` (with a codemod-injected fallback) or `color-mix(in srgb, var(--sina-*) N%, transparent)` for translucency. Run `node scripts/codemod-tokens.mjs` to inject/refresh the hex/length fallbacks; `node scripts/verify-tokens.mjs` and core's `src/offgrid-utilities.test.ts` fail on a raw color or a fallback-less `var(--sina-*)`.
- **Token naming follows one grammar** (`packages/theme/TOKEN_NAMING.md`): single `-` joins the identity path (category, semantic role/sub-role like `text-muted`/`primary-fg`/`focus-ring`, component, slot, multi-word property); a double `--` precedes a **leaf modifier** — a scale step, variant, size, or **state** — which comes **after** the property: `--sina-color-primary--hover`, `--sina-space--4`, `--sina-button-bg--primary--hover`. Roles stay single-dash; only values on a runtime axis (variant/state) get `--`; `focus-ring` is an atomic role. A vitest guard in `packages/theme/src/tokens.test.ts` fails the build if a state word follows a single dash.
- **The a11y bar** — every `core` primitive must meet **all four**: focus-trap + correct ARIA + full keyboard operability + **automated `axe` (jest-axe) pass**. Tests reuse core's `vitest.config.ts` (jsdom) and `vitest.setup.ts` (`toHaveNoViolations` already registered).
- **Error/warning states carry a bold status glyph.** Any `core` or `fintech-react` component that surfaces an **error** or **warning** state must render the matching **bold** Phosphor glyph beside the text — `Warning` (`weight="bold"`) for warning, `WarningOctagon` (`weight="bold"`) for error/danger — **never fill + text alone**. The companion status glyphs `Info` and `CheckCircle` (`weight="bold"`) cover info/success. This is the established Alert/Toast pattern (the `VARIANTS`/`TOAST_ICONS` maps in `packages/core/src/Alert/Alert.tsx` + `Toast/Toast.tsx`); mirror it, don't invent a new glyph. A caller may **swap** the glyph but not remove it for error/warning states. A vitest guard in `packages/core/src/error-warning-icon.test.tsx` renders each error/warning surface and fails the build if no `svg` glyph is present. Recipe: `/error-warning-icon`.
- **Never nest status elements inside one another.** A status element — `Alert`, `Toast`, or `Badge` (`@sina-design-system/core`) — communicates one self-contained intent and must **never** be rendered **inside** another status element (no `Badge` in an `Alert`, no `Alert`/`Badge` in a `Toast`, and so on). Compose them as **siblings**: a **text-only** `Alert` with any severity `Badge`s in a sibling row **beneath** it — the established `BlockedState` pattern (`apps/playground/app/(emulator)/_components/BlockedState.tsx`), a text `Alert` plus a sibling `styles.violations` list. Each core status root carries a `data-sina-status` marker (`alert`/`toast`/`badge`); a vitest guard in `packages/fintech-react/src/status-nesting.test.tsx` renders each status surface and fails the build if a `[data-sina-status]` element contains another. Recipe: `/no-nested-status`.
- **Docs stay small — budgets + one story, told once.** The docs (`apps/web/content/docs`) are capped at **20 prose pages** (outside `primitives/`) and **~700 prose words per page** (a page may declare a visible `wordBudget: <n>` frontmatter override); the canonical narrative assets (`FlowDiagram`, `ArchitectureDiagram`, `EnforcementLadder`, `TokenTree`, `GovernanceDemo`) each have exactly **one home page** — every other page links, never retells. Removed/moved pages get a **flat 301** in `apps/web/redirects.mjs` (fed to `next.config.mjs` `redirects()` — the only mechanism next-on-pages actually serves; a `public/_redirects` file silently 404s because the worker handles every path). Redirects never chain — point at the final URL — and every internal `/docs/...` link must resolve. Vitest guards in `apps/web/content/docs-{budget,canon,links}.test.ts` fail the build on any of these. Recipe: `/new-doc-page`.
- **Every core primitive has a live docs page.** Each `@sina-design-system/core` primitive ships a `content/docs/primitives/<slug>.mdx` in the shadcn shape — live hero demo first, Preview/Code examples, props table — backed by a `"use client"` demo module at `apps/web/app/components/docs/demos/primitives/<slug>.tsx` that the MDX imports **directly** (never registered in `mdx-components.tsx`, so demos stay code-split per page), plus a gallery card and `meta.json` entry. The slug list is derived from core's exports, so a new primitive without docs fails the build (`apps/web/content/primitive-docs.test.ts`). Never name a demo module `icon.tsx` (Next icon metadata-route collision — use `icon-demo.tsx`). Recipe: `/new-primitive-doc`.

## Contracts

- **Interception contract** — every schema returns this exact surface:
  `{ valid: boolean, violations: Violation[], requiredComponent: string | null }`
  - pass → `{ valid: true, violations: [], requiredComponent: null }`
  - fail → `{ valid: false, violations: [...], requiredComponent: "SecureWireDialog" }`
- **Audit event** — every interception emits:
  `{ timestamp, payload, result, violations, decidedComponent }`
  Contract now; the real sink is wired in Phase 10.

## Commands

- Whole workspace (delegate to Turbo): `pnpm build | dev | lint | typecheck | test`.
- Single package: `pnpm --filter <name> <script>` (e.g. `pnpm --filter @sina-design-system/core test`).
- Playground dev on **3001** (`pnpm --filter playground dev`); web on **3000**.
- Note: the `lint`/`typecheck` Turbo tasks `dependsOn: ["^build"]`, so a filtered dependent needs upstream `dist` to exist.
- **Apps consume built `dist/`, never `src`.** `apps/*` resolve `@sina-design-system/*` through each package's `exports`/`main` map (→ `dist/`); Next `transpilePackages` only transpiles, it does **not** redirect resolution to source. So an edit to a library's `src` is invisible to a running playground/web until that package's `dist` is rebuilt — this now includes **`dist/styles.css`**, which each app imports in `app/layout.tsx` (`theme/reset.css`, `theme/css`, `core/styles.css`, and `fintech-react/styles.css` for the playground). For iterative cross-package work run **`pnpm dev` from the repo root** (Turbo runs each library's `vite build --watch` alongside the app); `pnpm --filter playground dev` alone watches *only* the app and will serve stale library output. For a one-off check, `pnpm --filter <pkg> build` the edited library before verifying. Symptom of forgetting: stale UI (old icon/style) that makes a correct edit look broken — see `/preview-change`.
- **App styling is co-located CSS Modules too** (no Tailwind, no `tailwind.config`/`postcss.config`). Consume `--sina-*` tokens directly in app `*.module.css`.

## Deployment

- **The docs (`apps/web`) deploy to Cloudflare Pages automatically** via a Cloudflare Pages **Git integration** (project **`sina-docs`**; domains `sinahub.app` + `sina-28u.pages.dev`). Every push to `main` runs `pnpm --filter web pages:build` (`@cloudflare/next-on-pages`) → publishes `apps/web/.vercel/output/static`. There is **no** deploy step in GitHub Actions — `ci.yml`/`release.yml` only build/test + publish npm. Node is pinned by **`.node-version` = 22** (pnpm 11.9.0 needs Node ≥ 22.13; Node 20 crashes with `node:sqlite` — this broke CI/CF once already). **Cloudflare Pages serialises deployments per project** and serves the **last *successful*** build, so if a push builds green but the live site is stale, the CF build **failed** — read that deployment's build log on the Cloudflare dashboard, *not* GitHub Actions.
- **`apps/web` must stay Cloudflare-static-deployable (`next-on-pages`) — hard rule.** `@cloudflare/next-on-pages` emits a runtime function for **every Route Handler** (`app/**/route.ts`) — even `dynamic = "force-static"` ones (unlike Pages, which only warn) — and **requires it to run on the Edge runtime**. So a Route Handler must **never** import a Node builtin (`node:fs`, `node:path`, `node:crypto`, …) or otherwise need the Node runtime: it can't be Edge, and the **entire Pages build aborts** (this silently froze the docs at a pre-docs commit while every green `next build` masked it). To serve file/content-derived output, **generate it as a static asset at build** instead of reading at request time — the `apps/web/scripts/generate-llms.mjs` pattern (raw markdown → `public/llms/docs/**.md`, wired into `prebuild`). A vitest guard, `apps/web/app/cf-pages-safe.test.ts`, fails the build if any Route Handler imports a Node builtin. Recipe: `/cf-pages-safe`.

## Skills (repeatable recipes)

- `/new-governed-component` — scaffold a governed component in `fintech-react` (a `core` primitive composed with a `fintech` schema, re-gated server-side), wired into the playground harness. The `SecureWireDialog` recipe.

Enforces the "Error/warning states carry a bold status glyph" rule.

Enforces the "Never nest status elements inside one another" rule.
- `/cf-pages-safe` — before adding/editing any `apps/web` route, keep the site Cloudflare-static-deployable (`next-on-pages`): a Route Handler must not import a Node builtin (it can't run on Edge → the Pages build fails), so generate file/content-derived output as a static asset at build (the `generate-llms.mjs` pattern) and extend the `cf-pages-safe.test.ts` guard. Enforces the "`apps/web` must stay Cloudflare-static-deployable" rule.
