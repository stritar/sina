The best way to understand SINA is to watch it work. The demos below run the
**real gate** — the same code your server would run — at build time. Each shows the
request, the decision, and what mounted (or didn't).

A clean transfer, below every limit. The gate passes it and mounts an accessible

## Mock vs. live mode

The emulator can run three ways, and the decision is identical in all of them:

- **Mock** — a fixed, recorded request. Deterministic, no AI. This is what the docs
  and the test suite use.
- **Direct** — you hand-write the request as JSON. Good for probing edge cases.
- **Live** — a real model produces the request. It still only picks an intent; the
  gate treats its output exactly like any other.

<Callout variant="note" title="The gate doesn't care where the request came from">
  Mock, hand-written, or from a live model — it all hits the same server-side
  check. That's why the demo mirrors production instead of faking it.
</Callout>
