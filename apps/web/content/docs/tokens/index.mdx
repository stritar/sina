title: Tokens

A **design token** is a named value — a color, a spacing step, a font size — that
components reference instead of hard-coding. Change the value once and everything
pointing at it updates. In SINA, tokens are CSS custom properties, all prefixed
`--sina-`.

## Three tiers

Tokens are layered, so a raw value can change without every component knowing the
details.

<TokenTree />

- **Primitive** — a raw value in `theme.css`, like a specific green.
- **Semantic** — a *role* that gives the value meaning: `--sina-color-primary`
  means "the primary action color," whatever that happens to be.
- **Component** — a token scoped to one component, like `--sina-button-bg`, which
  points at a semantic role.

You almost always reach for the **semantic** tier. It answers "what does this
color *mean*," not "what hex is it" — so your UI stays consistent and re-themes
cleanly.

## The naming grammar

Token names follow one rule, so you can read a name and know what it does:

- A single dash joins the **identity** — the category, role, and property:
  `--sina-color-text-muted`, `--sina-space`, `--sina-button-bg`.
- A double dash marks a **leaf modifier** — a scale step, a variant, or a state,
  and it always comes last: `--sina-space--4`, `--sina-color-primary--hover`,
  `--sina-button-bg--primary--hover`.

<Callout variant="tip" title="Read it like a sentence">
  `--sina-button-bg--primary--hover` = the button's background, primary variant,
  hover state. Identity first, modifiers last.
</Callout>
