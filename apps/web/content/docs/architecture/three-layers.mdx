---
title: The Three Layers
description: theme → core → the Zod constitution and the governed components that render its decisions
---

SINA is built in layers that never blur into one another. Each has one job and
a hard list of things it may **not** contain. The layering is what keeps the
design system domain-agnostic while the governance stays enforceable.

## `theme` — tokens and reset

`@sina-design-system/theme` is the visual source of truth: the `--sina-*` CSS
custom properties in `theme.css` plus the CSS reset in `reset.css`, and the
typed token surface (`createTheme` / `themeVars`).

- **Its job:** own every color, space, radius, type, and duration value, so a
  token change propagates everywhere at once.
- **May not contain:** React, react-dom, or Tailwind. Tokens only.

## `core` — headless primitives

`@sina-design-system/core` is the accessible primitive library: headless React
components on Radix (`Dialog`, `Button`, `CurrencyField`, `Alert`, `Grid`,
charts, …), styled with co-located CSS Modules that consume `theme` tokens.
Every primitive meets the four-part a11y bar (focus-trap, ARIA, keyboard, axe).

- **Its job:** render accessible UI, domain-agnostic, mountable server-side.
- **May not contain:** `zod`, any domain package, any domain **vocabulary**
  (no `$50,000`, no "limit", no "approval"), and no Tailwind. A primitive knows
  nothing about wire transfers.

## `fintech` / `governance` — the constitution

`@sina-design-system/fintech` is the pure Zod constitution: the schemas that
validate an LLM's intent, each rule traced to a standard or regulator.
`@sina-design-system/governance` is the shared seam beneath it — the
interception contract, the audit emit point, and the `intercept` engine.

- **Their job:** decide whether an intent is valid and what must render.
- **May not contain:** React, `core`, `theme`, or any UI whatsoever.

## `fintech-react` — governed components

`@sina-design-system/fintech-react` is the third layer: it composes a `core`
primitive with a `fintech` schema and renders the decision the gate already
made (`SecureWireDialog`, and the presentational reads like `TransactionList`).
It is the **one** package allowed to import both `core` and `fintech` — but it
never authors schemas and never validates a payload itself; the gate stays
server-side.

## Seen end to end

A dashboard intent flows straight through the stack: `theme` supplies the
tokens, `core` supplies the primitives, `fintech` shape-validates the read, and
`fintech-react` mounts the presentational component the router resolved.
