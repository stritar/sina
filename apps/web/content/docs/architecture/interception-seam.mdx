The interception seam is the heart of SINA. It is the single point where an
LLM's intent meets the Constitution, server-side, before anything mounts.

## The seam

```
LLM stream (streamUI intent / tool payload)
        │
        ▼
[ fintech Zod schema .safeParse ]   ← the Constitution
        │
   ┌────┴────┐
 PASS       FAIL
   │           │
 render      BLOCK stream → force governed primitive
 core         (SecureWireDialog)
 primitive
```

## Walking the seam

**Intent in.** A `streamUI` flow (live) or a canned fixture (mock) produces an
`{ intent, props }` envelope. The model proposes a payload — it never names a
component.

**`.safeParse` — the Constitution.** The envelope is validated server-side
against the matching `fintech` Zod schema via `evaluateFintechIntent`. This is
the authoritative gate; anything on the client is untrusted UX sugar.

**PASS.** A compliant intent clears the schema and SINA mounts the pattern's own
`core` primitive — the standard render.

**FAIL.** A violating intent blocks the stream. The result's `requiredComponent`
names the governed component that **must** render instead, and SINA forces it.
The model's proposed render is discarded.

## Why the gate must precede the mount

With `streamUI` and React 19 RSC you cannot "un-render" tokens already streamed
to the client. So the check cannot run after a primitive mounts — by then the
tokens are gone. The schema gate sits **before** any `core` primitive is allowed
to mount, and it runs **only** on the server. This is
[The One Invariant](/docs/getting-started/the-one-invariant): validate, then
mount; never mount, then check.
