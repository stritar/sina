SINA は、AI がインターフェースの一部を生成するアプリケーション向けの、**ガバナンスを組み込んだデザインシステム**です。

モデルが、あなたの**ポリシー上限、コンプライアンス規則、アクセシビリティ基準**に違反する UI をレンダリングするのを防ぎます。


あなたはそれらの規則をコードとして記述します。モデルはインテントを送信し、サーバーがそれを検証し、そのうえで初めてコンポーネントがレンダリングされます。

これはごく普通の条件付きレンダリングであり、React が未ログインのユーザーにログインボックスを表示するときに行う選択と同じです。SINA はその選択をあなたのサーバーに移し、より難しい問いを突きつけます。そもそも AI はこれをレンダリングすべきだったのか、と。

違いは、誰が決めるかにあります。素の React では、`if` はあなた自身が書きます。SINA では、モデルが UI を提案し、あなたのサーバー上のルールがそれを表示するかどうかを決めるので、その `if` を手で書いた人は誰もいません。React は、モデルを信頼してよいかについて何の意見も持ちません。SINA が存在するのは、まさにそれを信頼できないからです。

## 解決する問題

AI に送金確認をレンダリングするよう頼めば、誰も承認していない 60,000 ドルのものであっても、あるいはスクリーンリーダーで操作できないドロップダウンであっても、レンダリングしてしまいます。出力は正しく見えるため、そのまま出荷されます。

SINA は代わりにレンダリング経路に位置します。モデルは
<Term term="intent">インテント</Term>を送信し、サーバーはそれを
<Term term="constitution">憲章</Term>（コードとして記述されたあなたの規則）と照合し、
通過したものだけがレンダリングされます。

<Callout variant="governance" title="ルール">
  モデルは提案し、サーバーが決定し、画面には通過したものだけが表示されます。SINA はこれを**検証してからマウント**と呼びます。
</Callout>

これらの規則はバージョン管理されたスキーマなので、それが下す一つひとつの決定は [監査イベント](/docs/concepts/audit-trail) として記録され、`if` の中に埋もれることはありません。

## 比較

| | 何か | 安全でない UI を止められるか？ |
|---|---|---|
| **スタイルガイド / wiki** | 人間（や AI）が無視できる助言 | いいえ、助言のみ |
| **コンポーネントライブラリ**（Radix、shadcn） | 優れたアクセシブルな部品 | いいえ、部品は誤用され得る |
| **SINA** | アクセシブルな部品**＋**サーバー側のチェック | **はい、コードで強制** |

SINA はコンポーネントライブラリの競合ではありません。（Radix 上のアクセシブルなプリミティブとして）*それを含み*、その上にチェックを追加します。

## 対象

SINA は**無料**（MIT）で、暴走しかねない AI の上にガバナンス層を自分で作り込むことなく、それを求めるスタートアップや個人開発者のために作られています。同梱の規則は現在 **fintech** を対象とします。送金、口座、カードです。

ガバナンスにはあなたから 2 つのものが必要です。UI を生成する AI と、チェックを実行するサーバーです。両方がなくても、SINA のアクセシブルなコンポーネントは[単体でも動作します](/docs/guides/adopt-incrementally)。ただしガバナンスは得られません。
