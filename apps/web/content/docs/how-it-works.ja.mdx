SINA における AI 生成の画面は、すべて同じ 3 つのステップを通ります。

1. **モデルが提案する。** AI は<Term term="intent">インテント</Term>を送信します。動詞に
   いくつかのデータを添えたもので、たとえば金額と受取人を伴う `"wire_transfer"` です。
   コンポーネントを指定することは決してありません。
2. **サーバーが決定する。** あなたのサーバーはインテントを
   <Term term="constitution">憲章</Term>、すなわち schema として記述したあなたの規則に通します。
   規則は 1 つの問いに答えます。これは許可されるか、そうであれば何をレンダリングすべきか、です。
3. **画面は通過したものを表示する。** SINA はサーバーが選んだコンポーネントをマウントします。
   リクエストが失敗した場合、安全でないものは一切レンダリングされません。

## すべてが依拠する唯一の規則

> **モデルが送るのはインテントと props であり、決してコンポーネントではありません。検証は
> サーバー上でのみ実行されます。私たちは検証し、_そのうえで_ マウントします。マウントしてから
> 確認することは決してありません。**

なぜブラウザではなくあなたのサーバーなのでしょうか。**UI が画面に届いてしまえば、もう取り
戻せない**からです。React はそれを少しずつストリーミングで送り下ろします。「アンレンダー」は
存在しません。

ですからチェックは**何かがマウントされる前に**実行されなければなりません。あなたが完全に
掌握できる最後の場所は、あなた自身の**サーバー**です。攻撃者はブラウザで動くものなら何でも
編集したりスキップしたりできます。そこでのチェックは正直な間違いは止めますが、**攻撃は止め
られません**。

それが見返りです。モデルが間違っていようと、ジェイルブレイクされていようと、敵対的で
あろうと関係ありません。**それが何をレンダリングするかを決めることは決してないのです。**

## インテントの見た目

```ts
const intent = {
  intent: "wire_transfer",
  props: { amount: 6000000, currency: "USD", recipient: /* … */ },
};
```

*そこにない*ものに注目してください。ボタンもなく、ダイアログもなく、レイアウトもありません。
AI は自分が*何を*望むか（「この金を動かす」）を記述するだけで、それが*どう*見えるべきかは
決して記述しません。

## ゲートが何をチェックするか

すべてのインテントは、同じ 4 つのステップを順番に通ります。

1. **構造。** payload はちょうど正しい形をしているか。schema は厳格なので、捏造された
   「確認」ボタンや紛れ込ませたカード番号は*余分なフィールド*であり、値が 1 つでも読まれる
   前に拒否されます。
2. **ポリシー。** 値は規則に従っているか。金額は上限内か。第 2 の承認者が必要か。
   すべてのしきい値は、実在する標準に基づいて引用されています。
3. **決定。** 問題は*違反*となり、ゲートが決定します。有効か否か、そしてより厳格な
   コンポーネントが必要なら、どれか、です。
4. **監査。** すべての決定は、何が求められ、何が決定され、どの規則が発火したかの記録を
   発行します。機微なデータは先に伏せられます。

決定は必ず 2 つのいずれかで終わります。**マウントされる**（リクエストが通過し、SINA は
規則が選んだコンポーネントをマウントする）か、**ブロックされる**（安全でない版は決して
マウントされず、そのまま拒否されるか、第 2 承認者ダイアログのようなより厳格な
コンポーネントへ<Term term="escalation">エスカレーション</Term>される）かです。

<Callout variant="note" title="ゲートはコンポーネントを名指しする">
  ゲートは「許可 / 拒否」を返すのではありません。*特定の 1 つの*コンポーネントを、
  `requiredComponent: "SecureWireDialog"` のように名指しするか、拒否します。マウント
  されるのはそのコンポーネントであり、他のものは何もありません。単なるポリシーエンジン
  ではなく、デザインシステムです。
</Callout>

## 3 つの層、1 つの流れ

内部では、SINA は 3 つの層でできています。token とプリミティブ、ガバナンスの継ぎ目、
そしてドメインの憲章です。あなたはたいてい上記の流れについて考えます。層は、それがどう
パッケージ化されているか、というだけのことです。

<Recap>
モデルはインテントを提案し、サーバーはそれを憲章と照合し、画面は通過したものだけを
マウントします。安全なリクエストは本物のコンポーネントになり、安全でないものは
ブロックされるか、統制されたコンポーネントへエスカレーションされます。
