SINA 是一个**内置治理的设计系统**，面向由 AI 生成部分界面的应用。

它可以阻止模型渲染违反你的**策略限制、合规规则或无障碍标准**的界面。


你把这些规则写成代码；模型发送一个意图；你的服务器对其进行校验，只有通过后组件才会渲染。

这就是普通的条件渲染，和 React 在向未登录用户显示登录框时所做的选择一样。SINA 把这个选择挪到你的服务器上，并交给它一个更难的问题：AI 究竟该不该渲染这个？

区别在于由谁来决定。在纯 React 中，`if` 由你自己来写。而在 SINA 中，模型提议 UI，你服务器上的一条规则决定它是否显示，所以没有人手写过那个 `if`。React 对能否信任一个模型并不关心；SINA 之所以存在，正是因为它不可信。

## 它解决的问题

让 AI 渲染一个转账确认，它就会渲染一个，哪怕是无人批准的 60,000 美元，或者一个屏幕阅读器无法操作的下拉菜单。输出看起来是对的，所以就上线了。

SINA 位于渲染路径之中：模型发送一个
<Term term="intent">意图</Term>，你的服务器依据
<Term term="constitution">章程</Term>（你用代码编写的规则）进行检查，
只有通过的内容才会渲染。

<Callout variant="governance" title="规则">
  模型提议；服务器决定；屏幕只显示通过的内容。SINA 称之为**先校验再挂载**。
</Callout>

由于这些规则是一份带版本的 schema，它做出的每个决定都会被记录为一次[审计事件](/docs/concepts/audit-trail)，而不是埋没在某个 `if` 里。

## 如何对比

| | 它是什么 | 能阻止不安全的界面吗？ |
|---|---|---|
| **风格指南 / wiki** | 人类（和 AI）可以忽略的建议 | 否，仅供参考 |
| **组件库**（Radix、shadcn） | 出色的无障碍部件 | 否，部件仍可能被误用 |
| **SINA** | 无障碍部件**加上**服务器端检查 | **是，由代码强制执行** |

SINA 不是组件库的竞争对手。它*包含*一个（基于 Radix 的无障碍基础组件），并在其上增加检查。

## 适合谁

SINA 是**免费的**（MIT），为想要治理层、又不愿在一个可能失控的 AI 之上自己动手搭建它的初创公司和个人开发者而打造。它内置的规则目前覆盖 **fintech**：资金流动、账户、卡片。

治理需要你提供两样东西：生成你界面的 AI，以及运行检查的服务器。如果两者你都没有，SINA 的无障碍组件[仍然可以独立使用](/docs/guides/adopt-incrementally)，只是你得不到治理。
