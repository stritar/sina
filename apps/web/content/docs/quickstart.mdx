Here's what you'll build: an AI sends a transfer, and your server decides what
renders. A safe amount mounts a real component; an over-limit one is blocked
and escalated. This demo runs the actual gate — try it before you install
anything.

<GovernanceDemo scenario="over-limit" />

<Prereqs>
- **Node 20+** and a package manager (pnpm, npm, or yarn).
- A React app that can run server code (a Next.js App Router project is ideal).
- You do **not** need an AI agent or an LLM key — you'll call the gate with a
  plain object.
</Prereqs>

<Steps>
  <Step title="Wire the stylesheets">

Import the token and component styles once, in this order (the reset is layered
so your app's styles always win over it):

```ts
// app/layout.tsx
import "@sina-design-system/theme/reset.css";
import "@sina-design-system/theme/css";
import "@sina-design-system/core/styles.css";
import "@sina-design-system/fintech-react/styles.css";
```

  </Step>
  <Step title="Gate an intent on the server">

The model sends an **intent** — a verb and some props. You run it through the
Constitution on the server and get back a decision. You never trust the client.

```ts
// app/actions.ts
"use server";
import { evaluateFintechIntent } from "@sina-design-system/fintech";

export async function gate(envelope: { intent: string; props: unknown }) {
  // → { valid, violations, requiredComponent }
  return evaluateFintechIntent(envelope);
}
```

  </Step>
  <Step title="Render the decision, not the request">

The decision tells you what to mount. On a clean pass, render the component the
gate chose. On a block, render the governed component it named — never the raw
one.

```tsx
// app/transfer.tsx
import { SecureWireDialog } from "@sina-design-system/fintech-react";

export async function Transfer({ envelope }) {
  const decision = await gate(envelope);

  if (decision.requiredComponent === "SecureWireDialog") {
    return (
      <SecureWireDialog
        intent={envelope.props}
        violations={decision.violations}
        onSubmitApproval={submitApproval} // re-gates on the server
        onApproved={onApproved}
      />
    );
  }
  return <TransferSummary {...envelope.props} />; // clean pass
}
```

  </Step>
  <Step title="Try both outcomes">

Send a $500 transfer — the summary mounts. Send $60,000 — the raw confirm never
appears; you get the second-approver dialog.

<Callout variant="tip">
  That's the whole guarantee, working end to end: the component you render is
  the one the *server* chose, not the one the request asked for.
</Callout>

  </Step>
</Steps>
