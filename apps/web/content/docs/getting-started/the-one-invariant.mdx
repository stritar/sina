The entire product rests on a single rule. We state it explicitly so we never
weaken it by accident:

> **The model emits _intent and props_ — never a component. Validation runs
> server-side only. We validate, _then_ mount. We never mount, then check.**

## Why it cannot break

With React Server Components you cannot "un-render" tokens already streamed to
the client. So the schema gate must sit **before** any primitive is allowed to
mount, on the server:

- The model proposes a **payload** describing what it wants. It may never name or
  select the component that renders.
- **SINA** decides what renders, by mapping the schema result to a
  `requiredComponent`.
- Client-side validation is treated as untrusted UX sugar. The authoritative
  gate is server-side — and that is the thing CI proves.

## Validate, then mount

```ts
// The model's proposal — intent + props, never a component.
const envelope = { intent: "wire_transfer", props: { amount: 60000 /* … */ } };

// The Constitution runs server-side and returns the decision.
const { valid, violations, requiredComponent } = evaluateFintechIntent(envelope);

// Only now does SINA choose what mounts. An over-limit transfer never renders a
// raw confirm — it is forced into the governed component.
```

A compliant $5,000 transfer clears the gate and mounts the standard primitive.
A $60,000 transfer is blocked and forced into `SecureWireDialog`, which requires
a secondary managerial approval that the stream cannot fabricate.

## What this buys you

Every later capability — governed money movement, masked data displays,
mandatory disclosures, and ungoverned read-only views — is judged against this
one invariant. If a hostile stream can bypass it, the feature is not done.
