Here's what you'll build: an AI sends a transfer, and your server decides what
renders. A safe amount mounts a real component; an over-limit one is blocked and
escalated. This runs the actual gate — try it before you install anything.

<GovernanceDemo scenario="over-limit" />

<Prereqs>
- **Node 20+** and a package manager (pnpm, npm, or yarn).
- A React app that can run server code (a Next.js App Router project is ideal).
- You do **not** need an AI agent or an LLM key to follow this — you'll call the
  gate with a plain object.
</Prereqs>

## Install

SINA is a set of small packages you compose. Add the five you need:

<Tabs>
  <Tab label="pnpm">

```bash
pnpm add @sina-design-system/theme @sina-design-system/core \
  @sina-design-system/fintech @sina-design-system/fintech-react \
  @sina-design-system/governance
```

  </Tab>
  <Tab label="npm">

```bash
npm install @sina-design-system/theme @sina-design-system/core \
  @sina-design-system/fintech @sina-design-system/fintech-react \
  @sina-design-system/governance
```

  </Tab>
  <Tab label="yarn">

```bash
yarn add @sina-design-system/theme @sina-design-system/core \
  @sina-design-system/fintech @sina-design-system/fintech-react \
  @sina-design-system/governance
```

  </Tab>
</Tabs>

<Steps>
  <Step title="Wire the stylesheets">

Import the token and component styles once, in this order (the reset is layered so
your app's styles always win over it):

```ts
// app/layout.tsx
import "@sina-design-system/theme/reset.css";
import "@sina-design-system/theme/css";
import "@sina-design-system/core/styles.css";
import "@sina-design-system/fintech-react/styles.css";
```

  </Step>
  <Step title="Gate an intent on the server">

The model sends an **intent** — a verb and some props. You run it through the
Constitution on the server and get back a decision. You never trust the client.

```ts
// app/actions.ts
"use server";
import { evaluateFintechIntent } from "@sina-design-system/fintech";

export async function gate(envelope: { intent: string; props: unknown }) {
  // → { valid, violations, requiredComponent }
  return evaluateFintechIntent(envelope);
}
```

<Callout variant="tip">
  You should now get a decision object back. For a clean $500 transfer,
  `valid` is `true`. For a $60,000 one, `valid` is `false` and
  `requiredComponent` is `"SecureWireDialog"`.
</Callout>

  </Step>
  <Step title="Render the decision">

The decision tells you what to mount. On a clean pass, render the component the
gate chose. On a block, render the governed component it named instead — never
the raw one.

```tsx
const decision = await gate(envelope);

if (decision.requiredComponent === "SecureWireDialog") {
  return <SecureWireDialog intent={envelope.props} violations={decision.violations} … />;
}
// clean pass → mount the standard component
```

<Callout variant="tip">
  Feed it the $60,000 transfer and the raw confirm never renders — you get the
  second-approver dialog. That's the whole guarantee, working end to end.
</Callout>

  </Step>
</Steps>
