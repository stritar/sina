`@sina-design-system/governance` is the shared seam every domain constitution
builds on: the contract each rule returns, the `intercept` engine that runs a
schema plus policy server-side, the intent router, and the audit emit point.
Domain-agnostic — **no React, no UI, no domain vocabulary**. `fintech` supplies
the rules and the component names.

## The contract

| Export | Purpose |
|---|---|
| `InterceptionResult` | The uniform `{ valid, violations, requiredComponent }` shape every rule returns. |
| `Violation` | A single failure — `code`, `message`, cited `standard`, `severity`. |
| `Severity` | The violation severity union. |
| `AuditEvent` | The structured `{ timestamp, payload, result, violations, decidedComponent }` event. |
| `SCHEMA_INVALID` | The sentinel violation code for a `.safeParse` failure. |

## The engine

| Export | Purpose |
|---|---|
| `intercept` | Runs a Zod schema + policy rules server-side and returns the `InterceptionResult`. |
| `ConstitutionRule` | The rule shape a domain implements (schema, optional policy, optional escalations, component). |

## The intent router

| Export | Purpose |
|---|---|
| `dispatch` | Resolve a single `{ intent, props }` envelope → a `Decision` (contract + mount). |
| `dispatchAll` | Resolve many envelopes (for composed experiences like dashboards). |
| `createRouter` | Build a router over a `PatternRegistry`. |
| `pattern` | Declare a `PatternEntry` (verb → rule + component). |
| `UNKNOWN_INTENT` | The sentinel for an unrecognized verb. |
| `IntentEnvelope`, `PatternEntry`, `PatternRegistry`, `Decision` | The router types. |

The router resolves the mount **outside** the `{ valid, violations,
requiredComponent }` contract, so governance stays an optional escalation layer
on a universal validate-then-mount.

## Audit

| Export | Purpose |
|---|---|
| `emitAudit` | Emit a redacted `AuditEvent` to the configured sink. |
| `redact` | Drop secrets and hash identifiers before an event is emitted. |
| `setAuditSink` / `resetAuditSink` | Install or reset the sink (a no-op by default; real sink lands in Phase 10). |
| `AuditSink`, `RedactionConfig` | The sink and redaction-config types. |

See [The audit trail](/docs/concepts/the-audit-trail) and
[The interception contract](/docs/concepts/the-interception-contract).
