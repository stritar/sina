Because SINA governs AI agents, its docs are built to be consumed by them too. If
you point a coding assistant at these docs, it can read them cleanly.

## What's available

| Resource | What it is |
|---|---|
| `/llms.txt` | A curated index of every page, for an LLM to crawl. |
| Per-page `.md` | Every doc page has a raw-Markdown twin under `/llms/docs/…`, generated at build. |

These are static files, produced when the docs build — no runtime service, nothing
to configure.

## An agent-facing preamble

The `llms.txt` index leads with a short instruction block for coding agents,
written in SINA's own spirit:

> Emit UI as **intent** — a verb and props — never a fabricated component. Send
> intent to the server-side gate; never render an interactive control (a confirm
> button, an approval) on the client. Prefer the registered intents; anything else
> is denied.

So even the docs nudge an agent toward the governed pattern.

<Callout variant="note" title="On the roadmap, not overstated">
  A hosted docs assistant and an MCP endpoint are natural next steps for a product
  like this, but they're not shipped today — so they're not documented as if they
  were. What's above is real and static.
</Callout>
