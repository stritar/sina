## 安定性とバージョン管理

SINA はまだ初期段階です。バージョンは semver に従い、Changesets を通じてリリースされます。

- **構築の土台にできる程度に安定**：トークンシステム、プリミティブ（アクセシブルでテスト済み）、インターセプト契約、そして
  fintech ゲート。これらは信頼できる形とテストカバレッジを備えています。
- **まだ進化中**：監査証跡は no-op のシンクを持つ定義済みの契約であり（永続的なシンクは計画中）、テーマ契約のガードは強化が進められています。
- **まだ未構築**：2 つ目のガバナンス領域、CLI、そしてホスト型のドキュメントアシスタント。アーキテクチャはそれらのための余地を残していますが、まだここにはありません。

<Callout variant="note" title="0.x は変更を見込むという意味">
  1.0 未満では、マイナーバージョンが破壊的変更を含むことがあります。バージョンを固定し、アップグレードの前にリリースノートを読んでください。
</Callout>

## 0.2.0：統合レビューによる強化

実際の統合レビューから得られた改善です。USD 以外の送金ペイロードはもう黙って通過しません。通貨が USD でない場合、各ポリシーは情報提供用の
`POLICY_BANDS_NOT_EVALUATED` フラグを付与するため、呼び出し側は金額バンドが評価されなかったことを確認できます（フラグは決してブロックしないので、結果は有効なままです）。各インテントマニフェストのエントリには
`propsSchema` が付くようになりました。これは自己完結型の JSON Schema で、LLM のツール定義にそのまま組み込めます。あわせて、各動詞をそのペイロードに結び付ける新しい
`IntentPropsMap` 型が追加されました。新しい未統制の動詞 `clarify_choice`（`ClarifyChoice` コンポーネント付き）が曖昧さの解消をカバーします。`list_cards`
の形状は必須フィールドを緩和し、送金は BIC なしの SEPA IBAN を受け入れ、`theme` に `./theme.css` エクスポートのエイリアスが追加されました。

## 0.1.0：初の公開リリース

最初に公開された範囲：デザイントークン + 型付きのテーマ API、28 個以上のアクセシブルなプリミティブ（チャートを含む）、共有のガバナンスの継ぎ目、完全な
fintech 憲章（統制されたフロー + 表示用の読み取り、すべてのしきい値を引用）、そして 3 つの統制されたコンポーネントです。
