`@sina-design-system/fintech` is the fintech Constitution: pure Zod schemas that
intercept and validate LLM intent server-side before it may render. **No React,
no UI.** Every rule traces to a standard or regulator, with the citation in the
code. It depends on `@sina-design-system/governance` for the shared contract.

## The gate entry point

| Export | Purpose |
|---|---|
| `evaluateFintechIntent(envelope, ctx?)` | The single entry point. Takes an `{ intent, props }` envelope, routes it to the matching rule, and returns the `Decision` (the interception contract + mount). |
| `fintechRegistry(ctx)` | Factory building the registry over the server-known approval context. |
| `fintechIntentManifest()` | The list of intent verbs SINA can render, as `IntentDescriptor`s. |
| `INTENTS`, `FintechIntent` | The intent-verb enum and its type. |

```ts
import { evaluateFintechIntent } from "@sina-design-system/fintech";

const { valid, violations, requiredComponent } = evaluateFintechIntent({
  intent: "wire_transfer",
  props: { amount: 6000000 /* $60,000 in minor units */ },
});
```

## Cited thresholds

`thresholds.ts` holds the legible numeric limits, each with a citation. A sample:

| Constant | Value | Cites |
|---|---|---|
| `TRAVEL_RULE_MINOR` | $3,000 | 31 CFR 1010.410(e) / 1020.320 |
| `SAR_MINOR` | $5,000 | 31 CFR Chapter X |
| `CTR_MINOR` | $10,000 | 31 CFR 1010.311 |
| `WIRE_SECONDARY_APPROVAL_MINOR` | $50,000 | SINA dual-control policy |
| `ACH_SAMEDAY_MAX_MINOR` | $1,000,000 | Nacha Operating Rules |
| `CRYPTO_TRAVEL_RULE_MINOR` | $1,000 | FATF R.16 / 31 CFR 1010.410 |

Amounts are integer **minor units** throughout — never floats.

## Format primitives

Reusable, cited Zod schemas (each also exposing a raw `isValid…` fn) under
`formats/*`: `currency` (ISO 4217), `amount` (the minor-units model), `iban`
(ISO 13616), `bic` (ISO 9362), `routing` (ABA), `card` (Luhn), `masked-account`,
`step-up` (the dual-control envelope), and `canonical`.

## Schemas

The constitution spans the full fintech surface — **governed** rules (policy +
escalation → a forced component: `wire-transfer`, `ach-transfer`, `p2p-payment`,
`kyc`, `add-payee`, `card-control`, `place-trade`, …) and **ungoverned** display
rules (shape-only → a presentational component: `transaction-list`,
`account-balance`, `spending-breakdown`, `portfolio-holdings`, …). Each ships a
`fixtures.ts` of valid + adversarial payloads. The full catalog is
`packages/fintech/PATTERNS.md`.

## Registry

`registry.ts` maps each intent verb → its constitution rule → the component the
gate mounts (the pattern's own on a pass, or the forced governed component on an
escalation).

See [The interception contract](/docs/concepts/the-interception-contract) and
[Add a schema](/docs/guides/add-a-schema).
