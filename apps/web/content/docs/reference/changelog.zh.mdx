## 稳定性与版本管理

SINA 尚处于早期阶段。版本遵循 semver，通过 Changesets 发布。

- **足够稳定，可放心构建**：令牌系统、基础组件（可访问、经过测试）、拦截契约以及 fintech
  关卡。它们具有可以依赖的形态和测试覆盖率。
- **仍在演进中**：审计追踪是一份已定义的契约，配有一个 no-op 接收端（持久化接收端已在规划中），主题契约的防护正在加固。
- **尚未构建**：第二个治理领域、一个 CLI，以及一个托管的文档助手。架构为它们预留了空间；但它们尚未到位。

<Callout variant="note" title="0.x 意味着预期会有变化">
  在 1.0 之前，次要版本可能带来破坏性变更。请固定你的版本，并在升级前阅读发布说明。
</Callout>

## 0.2.0：集成评审加固

来自一次真实集成评审的改进。非 USD 的资金转移负载不再静默通过：当币种不是 USD 时，每条策略都会附加一个信息性的
`POLICY_BANDS_NOT_EVALUATED` 标记，让调用方看到金额区间未被评估（结果仍然有效，因为标记从不阻断）。每个意图清单条目现在都带有
`propsSchema`，即一个自包含的 JSON Schema，可以直接放入 LLM 的工具定义中；同时还新增了 `IntentPropsMap`
类型，将每个动词与其负载绑定。一个新的未受治理动词 `clarify_choice`（配套 `ClarifyChoice` 组件）用于消歧。`list_cards`
的结构放宽了必填字段，电汇可接受不含 BIC 的 SEPA IBAN，`theme` 新增了 `./theme.css` 导出别名。

## 0.1.0：首个公开发布

首个发布的范围：设计令牌 + 类型化的主题 API、28+ 个可访问的基础组件（包括图表）、共享的治理接缝、完整的
fintech 章程（受治理的流程 + 展示读取，每个阈值均有引用），以及三个受治理的组件。
