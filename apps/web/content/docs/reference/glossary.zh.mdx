## 术语表

| 术语 | 含义 |
|---|---|
| **意图** | AI 请求显示 UI：一个动词加 props，绝不是一个组件。 |
| **章程** | 决定什么被允许的完整规则集（schema）。 |
| **关卡** | 每个意图都要经过的服务器端检查。 |
| **拦截** | 在任何东西挂载之前，让意图通过关卡。 |
| **先校验再挂载** | SINA 的核心规则：先在服务器上检查，再渲染。 |
| **拦截契约** | 统一的结果形态：`{ valid, violations, requiredComponent }`。 |
| **违规** | 关卡发现的一处问题，附带一条消息、一个严重程度和一个引用的标准。 |
| **严重程度** | 违规的作用力度：`flag`、`escalate` 或 `reject`。 |
| **升级** | 将被拦截的请求重定向到更严格的组件，而不是拒绝它。 |
| **受治理的** | 针对某个动作的规则，带有政策和可能的升级。 |
| **展示 / 未受治理的** | 针对某个读取的规则：检查其形态并进行掩码，绝不升级。 |
| **脱敏** | 在敏感数据被存入审计日志之前将其剥离/掩码。 |
| **审计事件** | 每个决定发出的记录。 |
| **双人复核** | 审批者必须不同于发起者的规则。 |
| **载荷绑定** | 将一次审批绑定到确切的条款，并在服务器上重新计算。 |
| **最小单位** | 以整数（分）表示的金额，遵循 ISO 4217。无浮点数。 |
| **基础组件** | 一个无头的、可访问的 core 组件（Button、Dialog、…）。 |
| **令牌** | 一个具名的设计值（颜色、尺寸、字体），以 `--sina-*` 变量的形式。 |
| **品牌开放 / 治理锁定** | 你可以重新主题化的令牌角色，相对于为安全保留的那些。 |
| **清单** | AI 可以发出的意图动词列表。 |

## 常见问题

**使用 SINA 需要 AI 或 LLM 密钥吗？**
不需要。你可以用一个普通对象调用关卡，而且文档会在没有任何密钥的情况下实时运行它。如果你只想要组件，[单独使用这些基础组件](/docs/guides/adopt-incrementally)。

**SINA 只适用于 fintech 吗？**
如今，是的。[治理接缝](/docs/reference/packages)是与领域无关的，因此另一个领域是[增量式的](/docs/guides/extend-sina)，而非重写。目前还没有构建任何一个。

**它能在 Next.js 之外工作吗？**
关卡需要一个地方来运行服务器端检查。Next.js App Router 是最顺畅的选择，但任何能够运行该检查的服务器都可以。这些组件是纯粹的 React。

**它可用于生产环境吗？**
发布于 **0.1.0**，所以还很早期。关卡和基础组件都经过了测试（包括一个对抗性测试套件和自动化的可访问性检查）；审计追踪是一份已定义的契约，配有一个空操作的接收端。请据此评估，并参见[发布与稳定性](/docs/reference/changelog)。

**许可证是什么？**
MIT，免费。SINA 的存在是为了让初创公司和个人能够采用一个受治理的设计系统，而无需自己构建治理层。

**关卡会增加延迟吗？**
这是一次同步的服务器端检查，一次 schema 解析加上政策，以毫秒计。关卡本身没有模型调用。

**SINA 会运行 AI 吗？**
不会。你运行你的代理；SINA 治理它的输出。模型提出一个意图，而 SINA 决定渲染什么。
