SINA is a **design system with governance built in**, for applications where an
AI generates part of the interface.

It stops a model from rendering UI that breaks your **policy limits, 
your compliance rules, or your accessibility standards**.


You write those rules as code; the model sends an intent; your server 
validates it, and only then does a component render.

This is ordinary conditional rendering, the same choice React makes when it
shows a login box to a signed-out user. SINA moves that choice to your server
and hands it a harder question: should an AI have rendered this at all?

The difference is who decides. In plain React you write the `if` yourself.
With SINA the model proposes the UI and a rule on your server decides whether
it shows, so no one wrote that `if` by hand. React has no opinion on whether a
model can be trusted. SINA exists because it can't be.

## The problem it solves

Ask an AI to render a transfer confirmation and it will render one, including
for $60,000 that no one approved, or a dropdown a screen reader can't operate.
The output looks correct, which is why it ships.

SINA sits in the render path instead: the model sends an
<Term term="intent">intent</Term>, your server checks it against the
<Term term="constitution">Constitution</Term>, your rules written as code, and
only what passes renders.

<Callout variant="governance" title="The rule">
  The model proposes; the server decides; the screen shows only what passed. SINA calls this **validate, then mount**.
</Callout>

Because those rules are a versioned schema, every decision it makes is recorded
as an [audit event](/docs/concepts/audit-trail), not buried in an `if`.

## How it compares

| | What it is | Stops unsafe UI? |
|---|---|---|
| **A style guide / wiki** | Advice humans (and AIs) may ignore | No, advisory only |
| **A component library** (Radix, shadcn) | Great accessible parts | No, parts can still be misused |
| **SINA** | Accessible parts **+** a server-side check | **Yes, enforced by code** |

SINA isn't a competitor to a component library. It *includes* one (accessible
primitives on Radix) and adds the check on top.

## Who it's for

SINA is **free** (MIT), built for startups and individual builders who want the
governance layer without hand-building it on top of an AI that can go off the
rails. The rules it ships with cover **fintech** today: money movement,
accounts, cards.

The governance needs two things from you: an AI that generates your UI, and a
server to run the check on. If you don't have both, SINA's accessible components
[still work on their own](/docs/guides/adopt-incrementally). You just don't get
the governance.
