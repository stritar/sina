SINA is a **design system with a gate**. When an AI builds part of your app's
interface, SINA checks that request on your server first — and only lets safe,
accessible, on-brand components through.

<FlowDiagram />

## The problem it solves

Letting an AI build UI is like giving a very fast intern write access to your
product. It doesn't know your limits, your compliance rules, or your
accessibility standards — and it will confidently ship something that breaks
them: a "Confirm" button for a $60,000 transfer no one approved, a dropdown a
screen reader can't use, data a user shouldn't see.

A style guide can't stop that — it *describes* good UI and hopes everyone
follows. SINA *refuses to render* bad UI. The AI never picks the component. It
sends an <Term term="intent">intent</Term> — a plain description of what it
wants to show — and your server checks it against the
<Term term="constitution">Constitution</Term>, your rules written as code. Safe
requests become real, accessible components. Unsafe ones are blocked or
redirected to a stricter, governed component. Nothing skips the check.

<Callout variant="governance" title="The one idea">
  The model proposes; the server decides; the screen only shows what passed.
  SINA calls this **validate, then mount** — check first, render second, never
  the other way around.
</Callout>

## How it compares

| | What it is | Stops unsafe UI? |
|---|---|---|
| **A style guide / wiki** | Advice humans (and AIs) may ignore | No — advisory only |
| **A component library** (Radix, shadcn) | Great accessible parts | No — parts can still be misused |
| **SINA** | Accessible parts **+** a server-side gate | **Yes — enforced by code** |

SINA isn't a competitor to a component library — it *includes* one (accessible
primitives on Radix) and adds the gate on top.

## Who it's for

SINA is **free** (MIT), built for startups and individual builders who want a
governed design system without building the governance themselves. It ships
today for **fintech** — money movement, accounts, cards, disclosures — because
that's where getting it wrong is most expensive.

It's probably *not* for you if you don't generate UI with AI (though you can
still [use the primitives on their own](/docs/guides/adopt-incrementally)), or
if you can't run a check on a server — the gate must run server-side.
