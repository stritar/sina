---
title: Write an Adversarial Test
description: Craft a hostile stream that tries to bypass the Constitution and prove it is blocked and forced into the governed component
---

An adversarial test is where SINA's promise gets proven. You craft a stream that
*tries* to bypass the Constitution and assert that it **cannot** — the intent is
blocked **before** any `core` primitive mounts. This guide mirrors the
`/adversarial-test` skill.

## 1. Pick the target

Choose a schema in `fintech` and the rule it enforces — say `wire_transfer` and
the $50,000 dual-control threshold.

## 2. Craft a hostile payload

Build a payload that *should* be blocked. Common shapes:

- An **over-limit** transfer (`amount` well above the cited threshold).
- A **fabricated** `requiredComponent` or an injected "Confirm" action the model
  invented — a bare button that claims to execute.
- **Malformed or extra fields** trying to slip past the schema.

```ts
const hostile = {
  intent: "wire_transfer",
  props: { amount: 6000000 /* $60,000 */, confirmed: true },
};
```

## 3. Assert the interception result

Run it through the gate and assert the block:

```ts
const { valid, violations, requiredComponent } = evaluateFintechIntent(hostile);

expect(valid).toBe(false);
expect(violations.length).toBeGreaterThan(0);
expect(requiredComponent).toBe("SecureWireDialog");
```

The key assertions: `valid` is `false`, the expected `violations` are present,
and `requiredComponent` is **forced** to the governed component. The model's
fabricated confirm is never the decided component — SINA chose the dialog.

## 4. Make it deterministic

Add the payload as a recorded fixture in **mock mode** (no live LLM) so the suite
is reproducible and CI-safe. Keep live-model mode for manual exploration only —
see [Mock vs. Live Mode](/docs/concepts/modes).

## 5. Wire it and verify

Wire the case into the playground adversarial suite and run
`pnpm --filter @sina-design-system/fintech test` (plus the playground suite in
mock mode). The adversarial suite is a required CI check — a rule is not "done"
until a hostile stream provably cannot break it.

See the block happen in [The Interception Seam](/docs/architecture/interception-seam).
