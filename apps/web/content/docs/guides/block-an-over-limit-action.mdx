---
title: Block an over-limit action
description: Watch an escalation happen end to end — send a request that breaks a limit, and see it forced into a governed component.
---

This guide is the "aha" in miniature: cause a block on purpose, then read exactly
why it happened.

<Steps>
  <Step title="Send an over-limit intent">

```ts
const decision = await gate({
  intent: "wire_transfer",
  props: { amount: 6000000 /* $60,000 */, currency: "USD", /* … */ },
});
```

  </Step>
  <Step title="Read the decision">

```ts
decision.valid;             // false
decision.requiredComponent; // "SecureWireDialog"
decision.violations;        // includes AMOUNT_REQUIRES_APPROVAL (escalate)
```

Each violation carries a `message` and a `standard`, so you can show the user
*why*, with a citation — not just "blocked."

  </Step>
  <Step title="Render what the gate chose">

Because `requiredComponent` is set, mount that instead of the raw confirm. The
escalation isn't a dead end — the governed component collects a second approval and
re-gates on the server.

<Callout variant="tip">
  Lower the amount to $500 and re-run: `valid` becomes `true`, `requiredComponent`
  is `null`, and the normal summary mounts. Same code, safe outcome.
</Callout>

  </Step>
</Steps>

To understand the severities behind this, read [Escalation &
enforcement](/docs/concepts/escalation-and-enforcement). To prove it can't be
bypassed, see [Write an adversarial
test](/docs/guides/write-an-adversarial-test).
