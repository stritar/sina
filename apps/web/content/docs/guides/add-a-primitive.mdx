---
title: Add a Primitive
description: Scaffold a headless, accessible core primitive — Radix base, theme tokens via CSS Modules, the four-part a11y bar, and a playground story
---

A `core` primitive is headless, accessible, and strictly domain-agnostic. This
guide mirrors the `/new-primitive` skill. The boundary is hard: **no `zod`, no
domain package, no domain vocabulary** (no `$50,000`, no "limit", no "approval"),
and no Tailwind.

## 1. Confirm design sign-off

Design sign-off gates implementation — it is binding. Build to the signed-off
anatomy and interaction states and to the `--sina-*` tokens; do not invent UX.

## 2. Build the component

Create `packages/core/src/<Name>/<Name>.tsx`:

- Import Radix as a namespace: `import { Dialog as Primitive } from "radix-ui"`,
  then `Primitive.Root`, `Primitive.Content`, …
- Relative imports use a **`.js` extension**; merge classes with
  `cn(styles.root, styles[variant], className)`.
- Add `"use client"` **only** if the file uses hooks, state, or interactivity.
  Pure presentational leaves stay server-mountable.

## 3. Style with a co-located CSS Module

Pair the component with `<Name>.module.css`: flat class names (`.root`,
`.primary`, `.sm`), real pseudo-classes for state (`.root:focus-visible`), and
Radix data-attributes (`.content[data-state="open"]`) — no BEM, no CSS nesting.
Declare a per-component `--sina-<name>-*` token layer aliasing the semantic
tokens and consume those. **Never write a raw color** except a codemod-injected
`var()` fallback — run `node scripts/codemod-tokens.mjs` to inject them.

## 4. Meet the a11y bar (all four)

Every primitive must pass **all four**, non-negotiable:

- **Focus-trap** (via Radix where a surface traps focus).
- **Correct ARIA** roles, states, and relationships.
- **Full keyboard operability**.
- **Automated `axe` pass** (jest-axe).

If the primitive surfaces an **error** or **warning** state, it must render the
matching **bold** status glyph beside the text (`Warning` / `WarningOctagon`) —
never fill plus text alone.

## 5. RSC export rules

- **Compound sets → individual named exports**, never one object — a single
  object export from a `"use client"` module resolves to `undefined` across the
  server/client boundary.
- **No function/render-prop children** on a client component used from a Server
  Component; wrappers take an element child and `cloneElement`.

## 6. Test and add a story

Add `<Name>.test.tsx` (RTL + `expect(await axe(container)).toHaveNoViolations()`
plus keyboard/focus assertions), then a playground story so the primitive can be
exercised in isolation.

Run `pnpm --filter @sina-design-system/core test`. See the `Button` and `Dialog`
references and `packages/core/CSS_TOKENS.md`.

Related reference: [`@sina-design-system/core`](/docs/reference/core).
