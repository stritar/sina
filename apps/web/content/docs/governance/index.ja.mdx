[仕組み](/docs/how-it-works)は SINA が*どのように*判断するかを説明します。この
セクションは*何を*です。fintech 向けに今日出荷されている実際の規則と、なぜそれらを
信頼できるのかです。

憲章は 2 種類の規則に分かれ、すべてのインテントはそのどちらかです。

- **統制された**規則は**アクション**を対象とします。送金、口座開設、カード発行です。
  ポリシー（上限、承認、開示）を伴い、より厳格なコンポーネントへエスカレーションでき
  ます。
- **表示**規則は**読み取り**を対象とします。残高、取引、保有です。データの*形*を
  チェックし（機微なフィールドをマスクし）、そのうえで表示用コンポーネントをマウント
  します。エスカレーションすることはありません。

どのインテントが存在し、それぞれが何をマウントするかの完全なカタログは
[統制されたコンポーネントと表示パターン](/docs/governance/components-and-patterns)です。

<Before title="プロンプトベースの規則">
「承認なしに 10,000 ドルを超える送金をしてはならない」はシステムプロンプトの中に
あります。それはモデルが混乱するか、ジェイルブレイクされるか、単に誤るまでしか
保たれません。

10,000 ドルの上限は、すべてのリクエストでサーバー側で実行される Zod のチェックです。
モデルは言葉巧みにパーサーをすり抜けることはできません。
</After>

## すべてのしきい値には出所がある

ガバナンスシステムは、その規則が*擁護できる*ものであって初めて信頼に足ります。だから
こそ、すべての規則はその出所を伴います。ゲートが何かをブロックすると、その違反には
`standard`、すなわちそれが由来する規制やポリシーが含まれ、その引用は
[監査記録](/docs/concepts/audit-trail)に残ります。ブロックが謎であることはありません。

コードは 3 種類の規則を区別して保ちます。**フォーマット**標準（ISO 4217、IBAN、
Luhn）、実在する金融規制に由来する**規制上**のしきい値（FinCEN の CTR、SAR、Travel
Rule の区分。FATF。Nacha）で、これらを軽々しく緩めるのはあなたの裁量ではありません。
そして**SINA ポリシー**のデフォルト値で、これらは自分のリスク許容度に合わせて調整する
ことが期待されています（50,000 ドルの電信送金の二重統制上限、決済経路ごとの承認上限）。

完全な一覧と、SINA が各項目について*実際に*何をチェックするかは
[標準と引用](/docs/governance/standards)です。

## 脅威モデル

SINA は、インテントを生成する AI が誤っている、ジェイルブレイクされている、あるいは
積極的に敵対的である可能性を前提とします。設計上の問いは決して「モデルは行儀よく
振る舞うか？」ではありません。「そうでないとき何が起こるか？」です。

| 攻撃 | 何を試みるか | なぜ失敗するか |
|---|---|---|
| **偽造されたコントロール** | `confirmButton` をペイロードに紛れ込ませる | 厳格なスキーマ。未知のフィールドは、いかなる値も読まれる前に拒否される |
| **紛れ込ませたカードデータ** | `cvv` または完全な PAN を含める | 同じ厳格な解析。編集（redaction）がログに達する前にマスクする |
| **上限超過のアクション** | 承認のない 60,000 ドルの電信送金 | ポリシーが第二承認者ダイアログへエスカレーションする。生の確認はマウントできない |
| **自己承認** | 自分自身の送金を承認する | 4 つの目のチェック。承認者はサーバーが把握している発起人と異なっていなければならない |
| **おとりのすり替え** | 5,000 ドルを承認し、その後 60,000 ドルを実行する | 承認は正確な条件に結び付けられ、サーバー上で再計算される |
| **偽造されたデータ** | 残高や取引をでっち上げる | 読み取りでは、値はサーバーが供給する。モデルは*何を*表示するかを選ぶだけ |
| **データ持ち出し** | マスクされていない口座番号を返す | 表示スキーマはマスクされた識別子を要求する |
| **フラッディング** | クライアントを固まらせるために 10,000 行を送る | 配列には上限がある |

<Callout variant="enforced" title="これらは仮定の話ではありません">
  上のすべての行は、SINA のテストスイートに含まれる実在のペイロードです。いずれかが
  ブロックされなくなるとビルドが失敗するため、これらの保証がひそかに腐ることは
  ありません。
</Callout>

これらの攻撃のいくつかが、実際の 1 つのリクエスト上で展開される様子をご覧ください。
[6 万ドルの電信送金、端から端まで](/docs/governance/wire-transfer)。そして
[自分自身の規則を書いてみましょう](/docs/governance/writing-a-rule)。
