SINA の黄金律は**上限を決して発明しないこと**です。あらゆる閾値、フォーマット、必須フィールドは、
標準または規制当局にまでさかのぼり、その引用がコードに記されています。このページはその証跡です。
憲章がコード化するすべての標準と、それぞれについて*コードが実際に何をチェックするか*を示します。

最後の列こそが要点です。標準の一覧はコンプライアンスの主張であり、コンプライアンスの主張こそ、
ガバナンスシステムがあなたに嘘をつき始める箇所です。だからこそ各行は、理想ではなく**メカニズム**を
述べます。SINA は IBAN の mod-97 チェックサムを実際に計算しますが、住所を制裁リストと照合することは
なく、PCI 評価を実施することもありません。ある規則が深い義務に対する薄い代用にすぎない場合、その行は
そう明記します。

規則は 3 つの階層に分かれ、コードはそれらを区別して保ちます。

- **フォーマット**：チェックサムとコードリスト。決定論的なので、ペイロードはそれらを満たすか満たさ
  ないかのどちらかです。
- **規制**：実在する規制。`flag` はその所見を[監査証跡](/docs/concepts/audit-trail)に記録し、
  `escalate` は統制されたコンポーネントを強制し、`reject` は端的に拒否します。軽々しく緩めてよいもの
  ではありません。
- **SINA ポリシー**：調整可能な製品のデフォルト値（デュアルコントロール、ステップアップ上限）。
  **法律ではありません。** これらは、あなた自身のリスク許容度に合わせて調整することが期待されるもの
  です。

ゲートがリクエストをブロックすると、一致した行の `standard` が違反とともに監査記録へと運ばれます。
ブロックが謎であることは決してなく、監査人はそれを引き起こした行まで遡ることができます。その形状に
ついては[契約](/docs/concepts/the-contract)を、規則を追加するには
[規則を書く](/docs/governance/writing-a-rule)を参照してください。

<Callout variant="enforced" title="この表はスキーマから生成されます">
  カタログはこのページではなく憲章パッケージに存在し、ガードテストが両者を結びつけます。カタログが
  省いた標準を引用する規則はビルドを失敗させ、どの規則も強制していないものを引用するカタログの
  エントリも同様です。ドキュメントはコードから乖離することはできず、存在しないチェックを主張すること
  もできません。
</Callout>

## ゲートが強制するもの、そしてどこで止まるか

SINA はレンダリング時のゲートであり、リクエストに対して五つの方法で作用します。構造と形式を検証し、しきい値を超えるとエスカレーションまたはフラグを立て、開示の確認を強制し、追加認証（step-up）または第二の承認者を要求し、そして監査証跡を墨消しします。下の各行は、この五つの動作のいずれかです。

三種類の制御は、意図的にこの範囲の外にあります。SINA は氏名や住所をリアルタイムの制裁リストや PEP リストと照合せず、バックエンドで融資や適格性の判断を下さず、資金移動業のライセンスも保有しません。いずれも UI ゲートには決して見えないサービスとリアルタイムのデータを必要とします。SINA はそれらの**前段**で動作し、それらを置き換えるものではありません。そのいずれかに依存する行は、その旨を明記します。

したがって、カバレッジの正直な姿は次のとおりです。資金移動のレールと報告のしきい値はここにあります。Travel Rule、SAR、CTR、デュアルコントロール、PCI のフィールド衛生です。制裁照合、公正な融資の判断、ライセンスは範囲外であり、範囲外として明示され、緑のチェックとして偽装されることは決してありません。ゲートの形をした規則のいくつかは、まだ構築されていないだけです。たとえば EU 向けフローの強力な顧客認証や、オープンバンキングのデータアクセス同意です。追加するには、[規則を書く](/docs/governance/writing-a-rule)を参照してください。

<Callout variant="note" title="範囲外であることは、穴ではなく機能です">
  ガバナンスシステムは、自らの境界を名指しすることで信頼を得ます。SINA はあなたの照合とバックエンドの判断の前段に位置するため、コードが決して実行しない検査をほのめかすよりも、境界をはっきりと述べることが安全な選択です。
</Callout>
